# Stop-line review — 2026-10-16 (plan items 1–4)

Standard §14.4: a root-cause class seen a third time stops the line until
we know why the existing countermeasure did not hold and have replaced it
with one that runs. Five RC classes and one candidate pattern crossed that
line during the reviews of PRs #5–#8 (ledger: `findings/ledger.json`,
F-01…F-40). This is the review.

The common answer to "why did the countermeasure not hold" is the same for
all five: **before this round Sakk had no class-level countermeasures, only
instance fixes plus rules written in AGENTS.md / RULES.md.** Every earlier
review fixed the finding in front of it; nothing checked the rest of the
code for the same shape. The mechanisms below are the first ones that run.

## RC-01 — assumption never verified, mostly "missing means OK" (13)

Pattern `fail-open-absence` (9): F-06, F-21, F-23, F-25, F-28, F-29, F-33,
F-09, F-16. A token the parser did not know, a file it could not read, a
case that never ran, a blob a join missed, spend that was never settled —
each was treated as "nothing to report" and the run read as success.

- Why it held on: each fix closed one input (the `=` form, one missing
  path) instead of the rule "absence is never success".
- Mechanism now: rule R-18; detector `test/cli-strictness.test.mjs` (every
  documented CLI refuses unknown/`=`/repeated arguments — commands are
  discovered from `--help`, so new ones are covered); detector
  `test/claims-are-checked.test.mjs` (every refusal code has a negative
  test); a third outcome INCOMPLETE in the bundle verifier for "intact but
  not final".
- Remaining exposure: library APIs called with missing optional arguments
  are not swept by a detector; review checklist until one exists.

## RC-10 — claim without verification (10)

F-02, F-03, F-05, F-19, F-22, F-26, F-27, F-33, F-36, F-37. Reports and
docs said more than their checks show: fake runs reading like model runs,
coverage counts that drifted, "every change is traceable", "cost equals
the ledger" while spend was open.

- Why it held on: claims were prose written apart from the code that backs
  them; the pack format made `gaps` mandatory but allowed them empty.
- Mechanism now: rule R-19; detector `test/claims-are-checked.test.mjs`
  (every code the docs name exists; every emitted code is tested); the
  README coverage count is computed by a test; every report carries its
  evidence strength (executor mode, model identity, INCOMPLETE).
- Remaining exposure: free-text claims ("traceable", "auditable") have no
  detector. Independent reading stays mandatory for pack JSON changes.

## RC-05 — untrusted input crosses a boundary (7)

F-01, F-12, F-13, F-17, F-18, F-35, F-07. Caller strings used as property
names; secrets printed in paths; a verifier vouching for itself; links
followed out of a tree.

- Why it held on: F-01 fixed the ledger's top level only.
- Mechanism now: detector `test/hostile-names.test.mjs` runs prototype
  names through every public entry point that takes a caller string
  (ledger, policy kernel, packs); own-key lookups in the ledger.
- Remaining exposure: new entry points must be added to that file by hand
  (stated in its header).

## RC-06 — tests that do not look like real use (7)

F-07, F-08, F-18, F-20, F-28, F-30, F-38. A test that rewrote the shipped
hook, plain file names only, absolute paths only, one benign umask.

- Why it held on: no rule required testing the artifact as shipped.
- Mechanism now: rule R-17; the stranger suite
  (`eval/__tests__/stranger-regressions.test.mjs`) and the hook-as-shipped
  tests are the homes for "how a stranger invokes it".
- Remaining exposure: R-17 is enforced by review, not by a detector.

## RC-07 — discipline by memory (3)

F-14, F-39, F-40. "Bump the schema" was a comment; "every refusal path has
a negative test" was a sentence in AGENTS.md (18 codes had none); a
rewrite dropped a check.

- Mechanism now: `test/schema-pins.test.mjs` pins closed key lists to
  their schema ids; `test/claims-are-checked.test.mjs` pins every emitted
  code to a test.

## RC-12 — checks that cannot fail (3)

F-15 (a hang instead of a red), F-24 (a gate test refused before the gate
it claimed to test), F-41 (`harness_dirty` could never be true). Each was
a check that looked green because it could not go red.

- Why it held on: new checks shipped with a test of one outcome only.
- Mechanism now: rule R-20 (every new check, flag or provenance field is
  driven both ways); positive controls in the gate tests (the G12 control
  in `eval/__tests__/case-packs.test.mjs`); every `node --test` script has
  `--test-timeout` and every CI job `timeout-minutes`, both checked by
  `test/claims-are-checked.test.mjs`; every emitted refusal code must be
  asserted by a test.
- Remaining exposure: boolean report fields have no generic detector —
  R-20 is enforced in review.

## Proposal S-1 — a new root-cause class in the standard (needs a decision)

`fail-open-absence` does not fit any RC in taxonomy v1: RC-01 ("assumed,
never measured") is the closest but loses the shape that matters — a
**missing** thing read as an **OK** thing. Nine findings in one day, in
three different components, is a class. Proposal: add
`RC-13 缺失即放行 (absence treated as success)` with countermeasure
"absence refuses or reads INCOMPLETE; every skip is counted and changes the
exit code". Changing the taxonomy changes every project's ledger, so it
goes through the decision template; until then these findings carry
RC-01 plus `pattern: fail-open-absence`.
